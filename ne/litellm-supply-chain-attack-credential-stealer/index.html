    LiteLLM मा प्रमाणपत्र चोर घुसाइयो: हप्तामा 2 करोड 30 लाख पटक डाउनलोड हुने एआई उपकरणमा आक्रमण

    अपहरण गरिएको रिलिज प्रणालीले बुधबार लोकप्रिय एआई गेटवेको विषाक्त संस्करण PyPI र Docker मा पठायो। करिब दुई घण्टा उपलब्ध रहेको त्यो संस्करणले स्थापना गर्ने हरेक मेसिनबाट क्लाउड कुंजी र पासवर्ड चोर्‍यो।

    • आक्रमणकारीहरूले एप र एआई मोडेल प्रदायकहरूबीच अनुरोध पठाउने लोकप्रिय खुला स्रोत उपकरण LiteLLM को रिलिज प्रणाली अपहरण गरी बुधबार, अक्टोबर 21 मा Python Package Index मा मालवेयरयुक्त संस्करण प्रकाशित…

    • LiteLLM का अनुसार घुसपैठियाहरूले आफ्ना तीन इन्जिनियरका GitHub खातामार्फत काम गरे, सम्भवतः चोरिएका GitHub CLI OAuth टोकन प्रयोग गरेर। एउटा खाता निजी रिलिज प्रक्रिया चलाउन र अर्को त्यसलाई स्वीकृत…

    आक्रमणकारीहरूले एप र एआई मोडेल प्रदायकहरूबीच अनुरोध पठाउने लोकप्रिय खुला स्रोत उपकरण LiteLLM को रिलिज प्रणाली अपहरण गरी बुधबार, अक्टोबर 21 मा Python Package Index मा मालवेयरयुक्त संस्करण प्रकाशित गरे। विषाक्त संस्करण 1.107.0 LiteLLM का आधिकारिक Docker छविहरूमार्फत पनि बाहिर गयो। Datadog Security Labs का अनुसार यो प्याकेज हप्तामा करिब 2 करोड 30 लाख पटक डाउनलोड हुन्छ, जसले यसलाई एआई विकासमा सबैभन्दा बढी प्रयोग हुने आधारभूत उपकरणहरूमध्ये एक बनाएको छ।

    मालवेयरले के गर्‍यो

    मालवेयरयुक्त संस्करणमा वास्तविक परियोजनामा नभएका तीन फाइल थिए: cook.pth, cook.py र sitecustomize.py। स्थापना भएपछि ती फाइल Python ले हरेक पटक सुरु हुँदा पढ्ने फोल्डरमा बस्थे, त्यसैले LiteLLM कहिल्यै प्रयोग नगरेका प्रोग्रामहरूमा पनि यो कोड चल्थ्यो। एउटा फाइलले प्रमाणपत्र चोर चलाउँथ्यो, जसले सुरक्षा फर्महरूका अनुसार SSH र GPG कुंजी, AWS, Microsoft Azure र Google Cloud का क्लाउड प्रमाणपत्र, Kubernetes र Docker गोप्य जानकारी, ब्राउजरका पासवर्ड र कुकी, तथा LiteLLM प्रोक्सी डाटाबेसमा राखिएका एआई प्रदायकका कुंजीहरू खोज्थ्यो। दोस्रो भाग हरेक घण्टा उठेर आक्रमणकारीहरूले नियन्त्रण गरेको सर्भरबाट नयाँ कोड तानेर चलाउँथ्यो, जसले उनीहरूलाई संक्रमित मेसिनहरूमा स्थायी पछाडिको ढोका दिन्थ्यो।

    विज्ञापन

    आक्रमणकारी कसरी भित्र छिरे

    LiteLLM का अनुसार घुसपैठियाहरूले आफ्ना तीन इन्जिनियरका GitHub खातामार्फत काम गरे, सम्भवतः चोरिएका GitHub CLI OAuth टोकन प्रयोग गरेर। एउटा खाता निजी रिलिज प्रक्रिया चलाउन र अर्को त्यसलाई स्वीकृत गर्न प्रयोग भयो, र त्यो प्रक्रियाले Berri-AI/litellm नामको दुर्भावनापूर्ण प्रतिलिपिबाट संस्करण बनायो, जुन वास्तविक BerriAI/litellm भन्दा एउटा हाइफनले मात्र फरक थियो। कम्पनीले संलग्न सबै टोकन रद्द गरेको छ र अनुसन्धान चलिरहँदा आफ्नो GitHub संगठनलाई एकजना अप्रभावित प्रयोगकर्तामा झारेको छ। LiteLLM का सुरक्षा निर्देशक Oliver Jensen ले टोकन कसरी चोरियो भन्ने टोलीले अझै नजानेको बताए।

    दुई घण्टा खुला रह्यो

    JFrog Security Research का अनुसार खराब संस्करण 11:39 UTC मा PyPI मा गयो र 13:23 UTC मा हटाइयो, करिब दुई घण्टाको अवधि। Docker का v1.107.0, latest, main-latest र main-stable ट्यागहरूले करिब 14:20 UTC सम्म विषाक्त छविहरूतिर देखाइरहे। Upwind, SafeDep, Socket र StepSecurity का टोलीले त्यही दिन विश्लेषण प्रकाशित गरे। यो यस वर्ष LiteLLM माथिको दोस्रो यस्तो आक्रमण हो: मार्चमा 1.82.7 र 1.82.8 संस्करणहरू TeamPCP समूहसँग पछि जोडिएको आक्रमणमा विषाक्त बनाइएका थिए, यद्यपि अनुसन्धानकर्ताहरूले दुई घटनाबीच कुनै सम्बन्ध स्थापित नभएको बताएका छन्।

    प्रयोगकर्ताले के गर्ने

    संस्करण 1.107.0 स्थापना गरेको जो कोहीले त्यो मेसिनका सबै प्रमाणपत्र खुला भएको मान्नुपर्छ। सुरक्षा फर्महरूले सफा 1.106.2 संस्करणबाट पुनः निर्माण गर्न, प्याकेज हटाउँदा पनि बाँकी रहने भएकाले रोपिएका तीन फाइल हातैले मेट्न, र क्लाउड कुंजी, SSH कुंजी तथा एआई सेवा टोकनहरू फेर्न सल्लाह दिएका छन्। प्याकेज मात्र हटाएर पुग्दैन, किनभने रोपिएका फाइलहरू त्यसबाहिर बस्छन् र घण्टे लोडर नरोकेसम्म चलिरहन्छ।

    स्रोतहरू

    The Hacker News, Datadog Security Labs, TechCrunch र SafeDep का रिपोर्टहरू, तल लिङ्क गरिएको छ।
